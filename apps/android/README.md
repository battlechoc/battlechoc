# battlechoc for Android (Trusted Web Activity)

The Play Store app opens `https://battlechoc.com` in Chrome without a URL bar (a Trusted
Web Activity). There is no native game code: the app is generated by
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) from `twa-manifest.json`.

It replaces the old WebView app and must keep its package name (`com.battlechoc.game`) and
signing key, so Play treats it as an update and not as a new app.

## Requirements

- JDK 17 (Bubblewrap does not work with newer JDKs) and the Android SDK command line tools.
  `npx @bubblewrap/cli doctor` checks both; on the first run Bubblewrap offers to download them.
- The upload keystore of the existing app (not in the repository). Put it next to this file
  as `battlechoc-upload.keystore` or point `signingKey.path` to it.

## Build

```bash
cd apps/android
npx @bubblewrap/cli@1.27.0 update --skipVersionUpgrade   # generates the Android project
npx @bubblewrap/cli@1.27.0 build                         # signed app-release-bundle.aab + APK
```

For CI, `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD` replace the password
prompts. Raise `appVersionCode` for every upload.

## Digital Asset Links

Chrome hides the URL bar only if `https://battlechoc.com/.well-known/assetlinks.json` lists
the SHA-256 fingerprint of the key that signs the installed app. With Play App Signing that
is the **app signing key** from the Play Console (Setup → App signing), not the upload key.
The file lives in `apps/pwa/public/.well-known/assetlinks.json`; the Pages workflow adds
`.nojekyll` so GitHub Pages serves the dot-folder.

## Push notifications

`enableNotifications` delegates notifications to Chrome, so Web Push (invites) works in
the app like in the browser.
