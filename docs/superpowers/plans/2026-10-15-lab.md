# The Lab Implementation Plan

> **For agentic workers:** executed inline (superpowers:executing-plans) in one run, as Fabian asked; every task is test-first.

**Goal:** Replace Choclab levels with equipment slots, an inventory of crafted items and a lab table that discovers recipes and crafts items.

**Architecture:** Item definitions and their effects live in the shared package and feed the engine through each player's loadout; the API owns inventory, recipes, discovery, crafting and loadouts; the PWA's Choclab page becomes the lab.

**Tech Stack:** as before (shared CommonJS + Jest, API Express + pg/pg-mem + Jest, PWA React 19 + react-jss + Playwright).

**Spec:** `docs/superpowers/specs/2026-10-15-lab-design.md`

## Global Constraints

- Branch `feat/lab` (on top of `feat/ingredients`); conventional commits without `Co-Authored-By`; never push or merge.
- Shared: CommonJS, 4 spaces, single quotes. PWA: `.jsx`, Prettier 2 style.
- Every UI text through `translate`, in all 8 language files.
- Item values round like the engine does today (whole numbers, at least 1).
- The production recipe table never goes into the repository.
- UI controls at least 44 px on touch; animations respect `prefers-reduced-motion`; every icon button has an accessible label.

## Review Focus

1. A player equips items, then loses one (crafted on another account? no, items cannot move) — instead: a loadout stored in the database that no longer fits the budget after a balance change must not crash or exceed the budget in a match (`sanitizeLoadout` everywhere).
2. Two crafts at once with ingredients for one: exactly one item, one serial.
3. A try with ingredients the player does not own, or for a building that does not exist, is refused without revealing anything.
4. Weapons created before an item is equipped keep their stats for that match only (loadouts are fixed at match start).
5. The refund migration on a player with levels and an empty pantry gives exactly the costs back.

## Tasks

### Task 1: Items and the engine (shared)

- Create `packages/shared/equipment.js` (`Items`, `Tier`, `LOADOUT_BUDGET`, `SLOTS_PER_BUILDING`, `sanitizeLoadout`, `applyStat`), export it.
- Engine: `createMatch` stores `players[].loadout` (sanitized); remove the level lookups (base values at level 0) and apply `applyStat` for hp, costs, cacao amount, build capacity/interval, donut interval/probability, fountain shield factor; weapons resolve cooldown, damage, entity factor, rush cost and rush start at creation; `weaponStatus` reads them; the view omits loadouts.
- Tests (`tests/engine/equipment.test.js`): each stat changes as the item says; sanitizing (unknown, wrong building, duplicates, over budget); levels no longer matter.

### Task 2: Refund and starter kit helpers, translations (shared)

- `progression.js`: `levelRefund(levels)` → `{ COCOA, … }` summed over `choclabCost` for every level below the current one; `StarterKit`.
- Translations: item names (`ITEM_<KEY>`), stat names (`STAT_<stat>`), lab texts (`LAB_*`), in 8 languages.
- Tests: refund sums; translation parity.

### Task 3: Database, recipes and lab routes (API)

- `db.migrate` runs `.js` migrations (`module.exports = async pool => …`).
- `004_lab.js`: `players.equipment`, `items`, `item_serials`, `recipe_discoveries`; refund levels into the pantry, levels to zero.
- `lab/recipes.js`: load and validate the recipe table (`RECIPES_FILE`, else `lab/recipes.sample.json`); `matchRecipe`, `smells`.
- `lab/routes.js`: `POST /lab/try`, `POST /lab/craft`, `GET /lab/recipes`, `GET /user/items`, `POST /user/equipment`; per-player try limit (30 per hour, configurable); crafts and equips one at a time per player in transactions; remove `/update/level`; the tutorial gives the starter kit; stats include `items`, `equipment`, `loadout`.
- Live: `playerSetup` adds the loadout; `startMatch` passes it to the engine.
- Tests: `test/lab.test.js` (all spec cases), the migration refund, the starter kit, a live match with a loadout.

### Task 4: Item icons and lab art (PWA)

- `public/images/lab/`: background (wall, shelves, table), bowl; effect badges (`hp`, `speed`, `damage`, `cocoa`, `cost`, `shield`, `donut`).
- `ui/lab/ItemIcon.jsx` (building icon in a tier-coloured frame plus the effect badge), `itemText.js` (effect and trade-off lines from `Items`).

### Task 5: The lab page (PWA)

- `ui/lab/Lab.jsx` replaces the Choclab page (same stage): carousel and 3D preview, two `EquipmentSlot`s, `BudgetBar`, `LabTable` with `Shelf`, `InventoryPicker`, `RecipeBook`, pantry button; offline read-only.
- Local matches pass `stats.loadout`.
- e2e `test/lab.spec.js`: finish the tutorial through the API, open the lab, select the truffle cannon, put sugar and milk on the table, try → discovered, craft, equip, the budget bar shows 2/10, a local match's truffle cannon reloads 20 % faster. Update `choclab.spec.js` (levels are gone).

### Task 6: Review and wrap-up

- Full test run (shared, API on pg-mem and Postgres, unit, simulator, build, e2e), screenshots of the lab in landscape and portrait checked against the UX constraints, memory notes, a fresh whole-branch review, fixes for Critical/Important findings.
